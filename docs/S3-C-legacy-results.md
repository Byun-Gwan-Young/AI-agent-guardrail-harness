# S3-C 기존 로그 적용 결과

기준: deadlock-v0.1
기준 스냅샷 SHA-256: bb10a3900e28aa5f5d2f4a62f57db79d71b1b82a63c0dda51dd11e398bb7dba5
결과 원본: reports/legacy-criteria-results.json. 입력 파일 SHA-256도 결과에 포함했다.

## 결론과 적용 범위
추가 가정 없는 정식 판정은 두 파일 모두 unmeasured다. 원본은 LLM 요청 배열이며
S3-A observations, 실제 작업 step 연결, 기준 버전, 종결 선언 문맥이 없다.
현재 rules-v1 추출기만 적용한 결과도 필요한 관측을 복원하지 못한다.
따라서 이 두 로그로 새 탐지기의 정확도/보존율을 검증했다고 보고할 수 없다.

조건부 대화 분석에서는 교착 로그의 6번째 요청에서 deadlock,
종료 실패 로그의 16번째 요청에서 최초 termination_failure 조건에 도달한다.
이는 실제 작업 step 탐지 시점이 아니라 '요청 1개=step 1개' 가정에 따른 번호다.
입력 부족을 가리기 위해 N을 바꾸지 않았다. 기존 문서값을 기대값으로 넣지 않았다.

## 관측 사실과 탐지 시점 추론의 구분
원본 응답에 나타난 RAM 제안값이 1→32→8→32→8→32로 변하고 이후 두 값 사이를 왕복한다는 사실은 로그에서 직접 확인한 관측 사실이다. 인접한 제안값은 매번 달라지므로 직전 값과의 동일성만 검사하는 단순 반복 검사는 이 패턴을 놓칠 수 있고, 이것이 이력 기반 왕복 탐지를 도입한 설계 근거다. 다만 모든 반복 탐지기가 실제로 통과시켰다는 비교 실험 결과는 아니다. 반면 '6번째 step에서 교착 탐지'는 요청 1개=step 1개, RAM만 평가, 종결 선언 없음 주석 등의 가정을 추가한 결과다. 왕복 패턴의 존재와 새 탐지기의 탐지 시점·정확도 검증을 구분해 보고한다.
## 제안값 왕복 분석 — assumed=true
RAM 제안값만 평가한다. 마지막 제안 표현 뒤의 RAM을 원문에서 추출했다.
다른 진행 정보는 이 분석에 포함하지 않는다. 종결 선언 없음은 원문 수동 검토 주석이다.

| 원본 요청 번호 | 제안 RAM(GB) | S3-A 상태 |
|---|---:|---|
| 1 | 1 | baseline |
| 2 | 32 | progress |
| 3 | 8 | progress |
| 4 | 32 | oscillating |
| 5 | 8 | oscillating |
| 6 | 32 | oscillating |

세 번 연속 oscillating에 도달한 시점이 최초 경보다. 이 투영 규칙은 운영 추출기에
추가하지 않았으며 새 실험의 자동 라벨 생성기로 사용하지 않는다.

## 종결 선언 이후 분석 — assumed=true
원본 13번째 요청의 확정·조달 준비 발화를 사람이 선언 위치로 주석 처리했다.
그 이후 빈 out만 new_info_ratio=0으로 투영했다. 산출물 활동이 없었다는 근거는 없다.
선언 전 상태는 미측정으로 두었으므로 선언 전 오탐 여부를 검증한 결과가 아니다.
11번째 요청에도 선택 의사가 있어 13번째가 유일하게 가능한 해석이라고 주장하지 않는다.

| 원본 요청 번호 | S3-A 상태 |
|---|---|
| 13 | unmeasured |
| 14 | stagnant |
| 15 | stagnant |
| 16 | stagnant |

선언 자체는 이전 비교 관측 부족으로 unmeasured지만, 다음 두 요청은 확인 유예,
그다음 연속 비진전 요청에서 종료 실패다. 이후 측정 불가 발화가 있으면 마지막
decision은 unmeasured가 될 수 있다. 최초 경보 시점은 별도로 보존한다.
로그의 세션 혼합 여부도 여전히 미확정이다. 1~5 요청을 임의로 삭제하지 않았다.

## 정상 배제와 회귀 검증
총 70개 테스트가 통과했다. 새 기준 검증은 합성 관측을 사용하며 실측 성능이 아니다.
- 쟁점이 닫히는 정당한 반복 검증: 교착 없음
- 파일 해시가 새 값으로 계속 바뀌는 조용한 작업: 교착 없음
- 종결 선언 뒤 1~2 확인 step: 교착/종료 실패 없음
- 누락 전후의 정체 구간을 이어 세지 않음
- test_plateau/regressed를 단독 실패 신호로 쓰지 않음
- 세션별 버전 저장·재시작 복원, 버전 없는 과거 세션의 소급 적용 방지

## 재현
프로젝트 루트에서 다음 명령을 실행한다. 외부 API 호출은 없다.
```powershell
python tools/evaluate_legacy_criteria.py --deadlock deadlock_log.json --termination termination_failure.json --termination-declaration-turn 13 --output reports/legacy-criteria-results.json
python -m unittest discover -s tests -p 'test_*.py' -q
```
--termination-declaration-turn은 수동 주석 입력이며 자동 탐지 결과가 아니다.
새 실험에서 관측/종료 문맥을 실제 수집해야 정식 판정이 가능하다. S3-B는 아직 진행하지 않았다.
