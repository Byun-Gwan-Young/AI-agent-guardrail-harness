# 데모 트랙 작업 분할과 규모 (C-16 파트 6)

- 상태 : **계획안.** 크레딧·시간은 **추정**이다. 계산 [demo_budget.py](demo_budget.py) → [demo-budget.json](demo-budget.json). 아래 숫자는 그 출력이다

### C-18 데모 트랙 3 — 시나리오 작성 + 시험 실행 명령

- 시나리오 **1 종(정상판+교착판 한 쌍)씩** 작성·보고 (14 장 "여러 시나리오를 한 번에 작성" 금지)
- 순서 제안 : CL (T3, 새 신호 확인) → CT → CT-N → CS → MR → LR (검색 API 의존이 큰 것을 뒤로)
- 코딩 과제는 정답 경로 검증. LR 가상 벤치마크 이름은 시험 실행에서 검색 0 건 확인
- PM 시험 실행 : 시나리오당 1 회 = **11 세션**, 크레딧 추정 범위 180.73 ~ 1438.96

### C-19 데모 트랙 4 — 본 실행 집계 + 재생 화면

- 관측 55 + 차단 15 결과, 유형별 "5 회 중 교착 k 회", 대표 세션 선정 근거
- 세션 재생 페이지 : 로그를 step 별로 재생하는 정적 HTML. 설명 문장·신호값·차단 시점 표시
- 데모 수치는 "데모 세션 기준" 으로만 표기 (DM-2)

## 4. 시간과 병렬 실행

- 벽시계 실측 (`reports/a-1-v4/c14-evidence.json`) : A-1-v3 87.4 초, A-1-v4 574.3 초
- 70 세션 순차 실행 포락 : **1.7 ~ 11.17 시간** (추정)
- 병렬이 **필요하지는 않지만 유용하다.** 상한이면 하루 작업이다. 동시 3 이면 **0.57 ~ 3.72 시간** (단순 나눗셈, 429·길이 차이 무시, 추정)
- 병렬을 쓰면 S-12 원칙을 그대로 적용한다
  - 프록시 1 개 = 조건군 1 개. 데모는 조건군이 둘이다 : **관측 프록시** (`guardrail-deadlock-v0.3-kmu.yaml`, 포트 8000) 와 **차단 프록시** (`…-block.yaml`, 포트 8001)
  - 세션을 두 프록시에 섞지 않는다
  - 동시 실행 3 으로 시작, 429 가 없으면 단계적으로 올린다 (S-12 절차)
  - 게이트웨이 한도 60 초 120 건은 프록시 두 개의 합으로 센다
  - 작업 폴더는 세션마다 별도 (현행 실행기가 이미 세션 폴더를 따로 만든다)
  - S-29 로 `logs/` 가 무시 대상이 되어, 앞 세션 로그가 뒤 세션의 dirty 판정을 막지 않는다
  - 데모는 `--dataset-run` 을 쓰지 않는다 (파트 4 안전장치)
- 병렬 실행 도구 자체(S-12 구현)는 C-20 범위다. 데모에서는 PM 이 터미널 창을 여러 개 여는 수동 병렬로 충분하다 (제안)
