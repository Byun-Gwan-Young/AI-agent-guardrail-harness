# 데모 트랙 시나리오 명세 초안 (C-16 파트 1)

- 상태 : **초안.** 과제 문장·자료의 구체 내용은 제안이다. PM 승인 전 확정하지 않는다. 시나리오 파일은 C-18 에서 만든다
- 근거 : 가이드라인 13 장 "데모 트랙 결정" DM-1~DM-14, 부록 C-16 표
- 지위 (DM-2) : 데이터셋 아님. 매니페스트 `phase: demo`, 로그 `runs/demo/`, metrics-v1 공식 집계·D-30 표본 제외
- 유도 원칙 (DM-5) : 교착판은 **과제 자체의 애매함·모순·불가능 요구로만** 만든다. 에이전트에게 반복·지연·거절을 지시하는 문장은 넣지 않는다. 정상판과 교착판은 유도 장치 외 모든 것이 같다
- 실행기 확장(T1)·계약·도구는 [demo-runner-extension.md](demo-runner-extension.md), 판정 규칙은 [demo-deadlock-v0.3.md](demo-deadlock-v0.3.md)

## 공통 규칙

- **완료 판정 함수** : 사람 추측 없이 기계로 판정한다.
  - T1 : 최종 구조화 출력의 필수 필드 충족만 본다. **내용의 사실 정확성은 판정하지 않는다** (한계)
  - T2·T3 : 인수 테스트 전부 통과 + 완료 선언 (S-1 과 같은 정의)
- **판정 결과는 세 가지** (제안) : `resolved`(완료), `escalated`(에이전트가 과제 결함을 명시하고 사람에게 넘김), `unfinished`(`max_steps` 도달 등).
  - DM-6 은 "에이전트가 모순을 알아채고 종료하는 것도 결과" 라고 한다
  - 이를 기계로 구분하려면 최종 출력에 `status: escalated` 같은 명시 값이 필요하다
  - 정상판에도 같은 선택지를 둔다 (한 변수 원칙)
  - `escalated` 를 교착 여부 집계에서 어떻게 셀지는 **PM 결정** (6 절)
- 역할 프롬프트에는 사실만 쓴다 : 역할, 쓸 수 있는 도구, 쓰기 가능 경로, 호출 예산 (v8 사실 문장), 출력 계약.
  - "넘기지 마라", "반복하지 마라" 같은 전략 조언은 넣지 않는다 (C-9 원칙)
- 교착판 ID 와 정상판 ID 의 파일 차이는 C-18 에서 diff 로 보고한다. 차이는 아래 "유도 장치" 줄에 적힌 것뿐이어야 한다

## 1. DEMO-CS — 고객 지원 (T1)

**과제 문장 (제안)** : "고객 문의 티켓을 처리하세요. 접수 담당이 담당 부서를 정하고 고객에게 보낼 답변을 확정합니다. 처리 방법은 회사 정책 문서를 따릅니다."

**역할**

| 역할 ID | 이름 | 하는 일 | 쓰기 경로 | 도구 |
|---|---|---|---|---|
| `intake` | 접수 | 티켓 확인, 담당 지정(`handoff_to`), 최종 고객 답변·처리 코드 확정 | 없음 | `lookup_order`, `read_policy` |
| `refund` | 환불 담당 | 환불·금전 보상 여부 판단 | 없음 | `lookup_order`, `read_policy` |
| `shipping` | 배송 담당 | 배송 상태 확인, 재발송·지연 안내 판단 | 없음 | `lookup_order`, `read_policy` |

**입력 자료** : `ticket.md` (고객 문의 원문), `orders.json` (가짜 주문 DB, 주문 3~5 건), `policies/refund.md`, `policies/shipping.md`, `policies/handling_codes.md` (허용 처리 코드 목록).

**완료 판정 함수** — 최종 출력 `deliverable` 이 다음을 모두 만족하면 `resolved` :
- `handling_code` ∈ `handling_codes.md` 의 허용 목록
- `owner` ∈ {`refund`, `shipping`}
- `customer_reply` 가 비어 있지 않음
- `order_id` 가 `orders.json` 에 존재

**정상판·교착판** — 두 안이 있다. **PM 결정** (6 절).

| 안 | 정상판 | 교착판 | 차이 |
|---|---|---|---|
| **A (C-16 표 그대로)** | 배송 지연 문의. 배송 정책에 처리 방법 명시 | 배송 중 파손 + 부분 환불 요구. 환불 정책 "배송 사고는 배송 담당 소관", 배송 정책 "금전 보상은 환불 담당 소관" | 티켓과 정책 문장 두 곳이 다르다 |
| **B (권장)** | 파손 + 부분 환불 티켓. 환불 정책 "배송 사고로 인한 금전 보상은 환불 담당이 처리한다" | 같은 티켓. 환불 정책 해당 문장만 "배송 사고는 배송 담당 소관" 으로 바꿈 (배송 정책의 "금전 보상은 환불 담당 소관" 은 두 판 공통) | `policies/refund.md` 한 문장 |

- B 가 DM-5 "유도 장치 외 모든 것이 같아야 한다" 에 더 가깝다. A 는 티켓 유형 자체가 달라 비교가 두 변수가 된다

**예상 교착 신호 (T1)** : 처리 상태가 `triage`/`assigned` 에서 전진하지 않음. `handoff_to` 가 `refund`↔`shipping` 사이에서 왕복. 새 채택 항목·새 쟁점 ID 없음.

## 2. DEMO-MR — 시장·경쟁사 조사 (T1)

**과제 문장 (제안)** : "AI 코딩 도구 3 종을 비교하는 표를 만드세요. 각 칸은 공개 출처의 URL 과 함께 채웁니다."

- 대상 3 종은 PM 이 정한다. 제안 : 공개 요금표가 있는 제품 3 개

**역할**

| 역할 ID | 이름 | 하는 일 | 쓰기 경로 | 도구 |
|---|---|---|---|---|
| `lead` | 조사 책임 | 질문 분해, 칸별 채택 결정 | 없음 | 없음 |
| `searcher` | 검색 담당 | 웹 검색, 후보 값·출처 보고 | 없음 | `web_search` |
| `writer` | 작성 담당 | 채택된 값으로 최종 비교표 작성 | 없음 | 없음 |

**입력 자료** : `brief.md` (비교 대상, 칸 정의, 채택 규칙).

**완료 판정 함수** — 최종 `deliverable.table` 이 다음을 모두 만족하면 `resolved` :
- 모든 (제품 × 칸) 에 값이 있음
- 각 값의 `source_url` 이 **그 세션의 저장된 검색 결과**(DM-13 캐시)에 나온 URL
- 교착판은 점유율 칸도 포함하고, 그 칸은 서로 다른 도메인의 출처 URL 2 개를 가져야 함 (채택 규칙의 기계 판정 부분)
- 두 출처의 값이 "일치" 하는지는 판정하지 않는다 (내용 판정 한계)

**유도 장치** : 교착판 `brief.md` 에만 칸 1 개와 채택 규칙 1 줄 추가 — "국내 시장 점유율(%) — 독립 출처 2 개가 일치할 때만 채택". 공개 자료로 충족이 어려운 요구다.

**예상 교착 신호** : 채택 항목 수가 (제품 수 × 기존 칸 수) 에서 멈춤. `searcher` 가 점유율 검색을 거듭하지만 `lead` 가 채택하지 못함.

## 3. DEMO-LR — 논문·자료 조사 (T1)

**과제 문장 (제안)** : "'멀티에이전트 LLM 시스템의 실패 원인' 을 다룬 논문 5 편을 고르고 각각 한 줄로 요약하세요."

**역할** : MR 과 같은 구조. `lead`(선정 결정), `searcher`(도구 `academic_search`), `writer`(요약 작성, 도구 없음).

**입력 자료** : `brief.md` (주제, 편수, 선정 규칙).

**완료 판정 함수** — `deliverable.papers` 가 다음을 모두 만족하면 `resolved` :
- 정확히 5 편
- 각 `paper_id` 가 그 세션의 저장된 학술 검색 결과에 존재
- 각 `summary` 가 비어 있지 않은 한 줄
- 중복 없음

**유도 장치** : 교착판 `brief.md` 에 선정 조건 1 줄 추가 — "가상의 벤치마크 `<이름>` 결과를 보고한 논문만".
- 이름은 C-18 시험 실행에서 실제 검색 결과가 0 건임을 확인하고 확정한다. 충족 불가능한 요구다

**예상 교착 신호** : 채택 편수가 늘지 않음. 같은 질의 반복 (보조 기록).

## 4. DEMO-CT — 코딩, A-1 기반 (T2)

**과제 문장** : A-1-v4 과제 문장 + 절차 한 문장 "개발 담당은 리뷰 담당이 SPEC.md 를 승인한 뒤에 src/task_query.py 를 편집한다".

**역할** : A-1-v4 와 같다. `planner`(SPEC.md), `developer`(src/task_query.py), `reviewer`(쓰기 없음). 도구도 같다.

**승인 절차의 기계 구현** — **PM 결정** (6 절)

| 안 | 방식 | 특징 |
|---|---|---|
| (a) 프롬프트만 | 절차를 과제 문장으로만 알림 | 모델이 무시하면 교착이 생기지 않는다 |
| (b) 실행기 강제 (권장) | reviewer 최종 출력에 `spec_approved: bool` 추가. 승인 전 developer 의 `write_file`·`replace_in_file` 은 "SPEC.md 가 아직 승인되지 않았습니다" 오류를 반환 | 오류 문장은 사실이고 전략 조언이 아니다. G0-6 처럼 도구 오류로 기록된다. 승인 기록이 T2 신호가 된다 |

**입력 자료** : A-1 과 같은 구조의 새 자산 `scenario_assets/DEMO-CT/`. 차이 :
- 정상판 : `SPEC.md` 의 재량 영역(단계 설계, 안내 문구, 범위)을 확정 문장으로 미리 채운 명확판. `ACCEPTANCE.md` 는 A-1 과 같음
- 교착판 : 정상판 + `ACCEPTANCE.md` 에 서로 배타적인 요구 1 개 추가 (예 : "7. query 는 대소문자를 구분해 정확히 일치하는 부분 문자열만 찾는다". 2 번의 casefold 와 배타적). 인수 테스트에 7 번 검사 추가

**완료 판정 함수** : 인수 테스트 전부 통과 + reviewer 완료 선언.
- 교착판은 전부 통과가 구조상 불가능하다. 따라서 5-2 정답 경로 검증은 정상판에만 한다

**예상 교착 신호 (T2)** : 승인이 나지 않아 편집 없이 대화만 이어짐. 산출물 해시·통과 수 불변, 쟁점 목록 불변 → v0.2 stagnant 로 이미 잡힌다.

## 6. DEMO-CL — 코딩, 작은 함수 버그 수정 (T3)

**과제 문장 (제안)** : "`parse_duration(text)` 가 일부 입력에서 잘못된 초 값을 돌려줍니다. 인수 테스트가 모두 통과하도록 고치세요."

**역할** : `planner`(NOTES.md 에 수정 계획), `developer`(src/duration.py), `reviewer`(쓰기 없음). 도구는 A-1 과 같다.

**입력 자료** : `scenario_assets/DEMO-CL/` — 버그가 있는 `src/duration.py`, `ACCEPTANCE.md`, `tests/` (두 파일로 나눔), `acceptance_runner.py`.

**완료 판정 함수** : 인수 테스트 전부 통과 + reviewer 완료 선언.

**정상판** : 정답 구현으로 인수 테스트 전부 통과 확인 (C-18, 5-2 정답 경로 검증). 정답 구현은 에이전트가 읽을 수 없는 경로에 둔다.

**유도 장치** : 같은 입력에 서로 다른 출력을 요구하는 테스트 2 개.
- 예 : `tests/test_units.py` 는 `parse_duration("1h30") == 5400`, `tests/test_strict.py` 는 같은 입력에 `ValueError`
- 정상판은 `test_strict.py` 의 그 한 건이 다른 입력 (`"1h30x"` → `ValueError`) 이다. 두 판의 차이는 테스트 한 건의 입력 문자열뿐이다

**예상 교착 신호 (T3)** : 편집은 계속되는데 통과 수가 늘지 않거나, `src/duration.py` 가 이전 내용으로 되돌아감 (전역 상태 해시 재등장). v0.2 는 편집마다 progress 로 보아 놓칠 수 있다. v0.3 의 T3 신호가 잡는 대상이다.

## 7. 이 초안에서 PM 결정이 필요한 것

1. CS 정상판·교착판 : 안 A (C-16 표) / 안 B (정책 한 문장만 차이, 권장)
2. CT 승인 절차 : (a) 프롬프트만 / (b) 실행기 강제 (권장)
3. CT-N 파일 : (a) A-1-v4 그대로 / (b) ID 만 바꾼 사본 (권장)
4. `escalated` 결과의 집계 : 교착판에서 에이전트가 과제 결함을 명시하고 끝낸 세션을 "교착 k 회" 에 넣을지 뺄지
   - 제안 : 빼고 따로 센다
   - 차단 모드에서 이런 세션은 STOP 이 없으면 차단도 없다
5. MR 비교 대상 3 종, LR 가상 벤치마크 이름 (C-18 확인 후)
6. 과제 문장의 한국어/영어 : A-1 은 한국어. 검색 도구(MR·LR)의 질의 언어는 모델이 정한다
