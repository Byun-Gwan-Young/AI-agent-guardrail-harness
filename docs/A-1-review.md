# A-1 검토용 요약

## 과제와 역할
애매한 업무 조회 요청을 기획·구현·리뷰로 완성
팀 업무 목록 검색·상태 필터·정렬·페이지네이션 기능을 완성한다.
기획은 SPEC.md, 개발은 src/task_query.py를 수정하고 리뷰는 실제 테스트로 검수한다.
공개 ACCEPTANCE.md의 최소 조건은 고정이며, 역할 충돌이나 교착을 강제하지 않는다.
기획 재량은 내부 처리 단계·안내 문구·범위 설명이다. 기대 결과는 unknown이다.

## 수집·종료
progress_source=both. 대화는 open_issues_count/new_info_ratio,
산출물은 test_pass_count/files_changed를 관측한다. 선택하지 않은 지표를 0으로 채우지 않는다.
A 구조화 관측과 narrative만으로 추출한 B를 구분해 보관한다.
리뷰어의 구조화 완료 선언과 테스트 기반 성공을 따로 확인한다.
criteria_version=deadlock-v0.1, 관측 경보에 의한 차단은 없다.
실행 상한은 18 step, step당 모델 요청 최대 2회다.

## 예상 토큰 — assumed=true, 실측 아님
예상 모델 요청 9~15회,
max_tokens=1200, 평균 입력 2000토큰,
평균 출력은 max_tokens의 50%를 가정한다.

| 구분 | 가정 기반 계산 |
|---|---:|
| 입력 | 18,000~30,000 |
| 출력 | 5,400~9,000 |
| 입출력 합계 | 23,400~39,000 |
| 예상 호출 수에서 출력 제한 합계 | 10,800~18,000 |
| 실행 상한까지 도달했을 때 출력 제한 합계 | 43,200 |

마지막 값은 재시도를 제외한 출력만의 제한이며 총 토큰 상한은 아니다.
실제 문맥 누적·도구 후속 호출·재시도에 따라 달라진다. seed는 지원 미확인으로 null이다.
