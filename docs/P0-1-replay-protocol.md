# P0-1 replay 사전 판독 규칙

결과를 보기 전에 고정한다. 입력: logs/A-1-82c393c248a34286b318f344f2e181e4.json.
새 계산: progress-v2 / deadlock-v0.2. N, grace_steps, missing_review_steps는 전역 step.

1. 원본 JSON 바이트 SHA-256을 기록한다. 원본 관측·판정·버전·라벨은 수정하지 않는다.
2. 모든 step의 v1 progress와 v0.1 criteria를 먼저 재계산한다. 저장된 각 결과와
   동일한 JSON 직렬화(ensure_ascii=False, 정렬 없음)의 UTF-8 바이트를 비교한다.
   하나라도 다르면 v2 계산 및 결과 쓰기 전에 예외로 즉시 중단한다.
3. 원본 관측에 agent_id가 없으므로 역할은 연결된 LLM 요청의 system 메시지에서
   복원한다. A-1 YAML의 각 역할 system_message 첫 줄을 명시적 매핑 규칙으로
   사용한다. 해당 문자열로 시작하는 시스템 메시지가 한 역할만 지시할 때만 배정한다.
   turn 번호·메시지 위치·일치 문자열·규칙 파일 해시를 기록한다. 이는 사후 메타데이터
   복원이며 원본에 agent_id가 저장돼 있었다는 뜻이 아니다. 순환 번호로 추정하지 않는다.
   미일치/충돌 시 agent_id=null, status=unmeasured이며 전역 비교로 대체하지 않는다.
4. 관측의 지표·null·종결 문맥은 그대로 사용한다. step 5·10·13·16·18의 폐기된
   관측은 복원하지 않는다. 공백을 동일 역할 이력에 남기고 마지막 유효 관측으로
   건너뛰지 않는다. response_body에서 최종 출력을 재파싱하지 않는다.
5. 성공 기준은 역할 간 쟁점 ID 차이에 기인한 progress가 제거됐는지다. 이전 비교
   역할이 다르고 쟁점 ID 이벤트가 있는 행을 표시한다. 그중 기존 progress의 비왕복
   이벤트가 전부 쟁점 ID 이벤트인 행은 역할 간 쟁점 ID로 발생한 progress 후보로
   분류한다. 같은 역할의 쟁점 집합이 실제 바뀌는 경우는 별도 표시해 혼동하지 않는다.
   산출물 등 독립 비왕복 이벤트도 있던 행은 혼합 원인으로 분리한다. 제거 수·잔존 수는
   행에서 계산하며 기대 개수나 기대 step 판정을 하드코딩하지 않는다.
6. 새 결과에 과거 전역 관측에서도 관측된 동일 산출물 상태로의 변화가 나타나면
   공유 산출물 재관측으로 표시한다. 해당 역할이 변경했다는 인과 주장이 아니다.
7. 각 행에 현재 폐기 공백, 같은 역할 직전 공백, 현재/직전 info_items null,
   실제 미측정 metric과 이유를 기록한다. baseline, progress와 누락이 공존하는
   경우도 그대로 기록한다. 경보 부재는 P0-1 실패 조건이 아니다.
8. 미측정 탐지 성능·실제 STOP 시점은 null/status=unmeasured로 둔다.
   replay는 관측 비교 범위 변경 분석이며 새 실측 실행이나 교착 정답 검증이 아니다.
