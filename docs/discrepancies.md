# 문서와 구현의 불일치

## S2 — 429 지수 백오프가 구현 완료로 기재된 오류

원본 CODEX_작업명령서.md의 Phase 6 T6-2에는 업스트림 429 지수 백오프
최대 6회가 구현 완료라고 기재되어 있었다. 실제 legacy proxy.py는
range(6)으로 총 6번 호출하고 매 429 뒤 고정 8초를 기다렸다.
마지막 시도 뒤에도 대기했으며 지수 증가와 지터는 없었다.

S2에서 수정: 최초 요청 + 최대 6회 재시도(총 최대 7회), 429만 재시도.
0부터 시작하는 재시도 번호 n에 대해 ceiling=min(60초, 2^n초),
delay=ceiling/2 + Uniform(0, ceiling/2)인 equal jitter를 사용한다.
6회 대기 범위는 각각 0.5~1, 1~2, 2~4, 4~8, 8~16, 16~32초다.
성공 또는 429 이외 응답이면 중단하고, 마지막 429 뒤에는 대기하지 않는다.
최종 응답 하나를 한 턴으로 기록한다. 각 시도는 별도 턴으로 세지 않는다.

검증은 MockTransport 429 응답과 가상 시계·대기 함수를 사용했다.
지터를 구간 중간값으로 고정하면 대기는 0.75, 1.5, 3, 6, 12, 24초였다.
이는 모의 검증값이며 실환경 지연 측정값이 아니다. 외부 API는 호출하지 않았다.

## S2 — 측정 가능한 항목의 한계

tool_calls는 응답에서 관측한 도구 호출 요청 수이다. 프레임워크의 실제 도구 실행
횟수는 프록시만으로 검증할 수 없다. 정상 응답에 호출이 없으면 0, 오류나 해석
불가능한 응답이면 null이다.
seed 지원 여부를 외부에서 확인하지 않았다. 미등록 모델은 seed=null,
seed_status=unverified다. 지원을 확인한 모델만 설정에 true/false로 기록한다.
seed_supported=false면 seed=null, unsupported와 미지원 설명을 남기고 seed를
업스트림 요청에서 제거한다. true여도 기록값은 요청 조건이며 결정성 보장이 아니다.
