# 004 역할별 진전도 비교 — P0-1

## 범위와 입력 계약
역할마다 다른 쟁점 ID를 직전 전역 step과 비교해 변화로 세는 문제를 고친다.
관측 최상위 agent_id는 실행기만 넣는 메타데이터다. 모델 출력 스키마, 검증,
프롬프트에 역할 식별자를 요구하지 않는다. 실패 step의 역할도 실행기가 안다.
관측 API는 인증된 역할을 추론하는 기능이 아니며 호출자가 전달한 메타데이터를
검증·보관한다. 기존 스키마 입력을 위해 agent_id 누락은 허용한다.

## 승인된 설계
저장 원본 observations는 전역 step 순서 그대로 둔다. 계산 시 동일 agent_id의
원본 관측 참조만 선택해 직전 비교와 전체 과거 이력 검색에 사용한다. 이 파생
이력은 별도 저장하지 않으므로 재시작 때 원본에서 동일하게 재구성된다.
대화와 산출물 모두 역할별 비교이며 공유 산출물 변경은 여러 역할에서 관측될 수 있다.
첫 역할 관측은 기존 첫 관측 규칙대로 baseline 또는 unmeasured다.
공백 관측을 삭제하거나 마지막 유효 관측으로 건너뛰지 않는다.

progress-v2 / deadlock-v0.2를 신규 버전으로 사용한다. N=3은 전역 step 연속이다.
grace_steps=2와 missing_review_steps=3도 전역 step 기준을 유지한다.
역할별 카운터·순환별 카운터는 도입하지 않는다. 경보는 observe_only이며 자동 STOP을
추가하지 않는다. 기존 세션은 생성 시점의 버전으로 계산하며 과거 결과를 덮어쓰지 않는다.

## 범위 밖 얽힘
실패 step 관측 복원(P0-2), 쟁점 ID 표준화(P0-3), info_items null(P0-4),
progress/unmeasured 우선순위는 변경하지 않는다. 공유 파일의 동일 변경이 여러
역할에서 progress가 될 수 있으며 현재 역할의 수정 성과라는 의미는 아니다.
