# 데모 집계 도구 · 세션 재생 페이지 (C-19-1)

- 상태 : C-19-1 구현 기록 (브랜치 `c19-1-aggregate-replay`, 별도 worktree. 본 실행 종료 전 main 에 반영하지 않음, DM-69)
- 근거 : 가이드라인 13 장 DM-2·DM-6·DM-18·DM-23·DM-46·DM-48·DM-62~DM-69, S-1·S-20·S-27, 결정 문서 022·023
- 입력은 커밋된 시험 세션 기록(`demo-records-v1`)과 시험 세션의 로컬 원본뿐이다. 본 실행 세션 파일은 읽지 않았다
  (원본은 시험 세션 ID 를 하나씩 지정해 읽었다)

## 재생 기록 `record/replay.json` (`demo-replay-v1`, `tools/replay_demo.py extract`)

- 로컬 원본(`steps.json`, `session.json`, `conditions.json`, `summary.json`)에서 페이지에 필요한 값만 뽑는다 : step 마다 역할 표시 이름,
  최종 보고의 구조화 필드 사실(처리 상태와 표시 이름, `handoff_to`, 채택 항목 수, 열린 쟁점 ID, 결과물 보고 여부, SPEC 승인, 완료 선언),
  완료 주장과 판정 결과, 도구 이름과 오류 여부, 인수 테스트 통과 수, 바뀐 파일 경로, 진전 상태(되돌림 표시 포함), 판정과 STOP 원인 설명 문장,
  그 step 의 토큰(입력·캐시 입력·출력·reasoning 개수)과 추정 크레딧, 누적값
- **넣지 않는 것** : narrative, `info_items`, 결과물 값, 도구 출력, 모델 reasoning 내용 (테스트로 확인)
- "여기서 멈췄다면" : 첫 STOP step 뒤 step 들의 토큰(입력 + 출력)과 추정 크레딧. 차단 프록시가 STOP 다음 요청을 거절하는 것(DM-7)과 같은 기준
- 시험 세션 12 개의 재생 기록 합계는 세션 요약의 토큰·추정 크레딧과 모두 같다 (CL 정상판 첫 시도 `c3a4c019…` 는 usage 없는 400 이라 크레딧 미측정)
- `tools/demo_records.py record` 가 이 파일도 쓰고, `COMMIT_FILES` 에 **선택 파일**로 넣었다 (필수 파일 목록은 그대로라 이전 세션 기록도 규칙을 지킨다)

## 집계 `tools/aggregate_demo.py` (`demo-aggregate-v1`)

- 입력 : `--plan`(본 실행 `demo-main-v1`)의 세션(`conditions.json` 의 `batch.plan_id`)과 `--session` 으로 지정한 세션. 커밋되는 기록 파일만 읽는다
- 제외 : `--final-freeze-sha256` 를 주면 `batch.final_freeze_sha256` 가 다른 세션. 같은 시나리오·모드의 다수 조건군과 다른 세션. 제외 목록과 사유를 출력한다.
  시험 계획에는 동결 기록이 없으므로 해시 없이 돌리고 출력에 "not applied" 로 남긴다
- 종료 분류 (DM-18·DM-46·DM-48) : 성공 / 미완료(`max_steps`, 차단 모드의 `guardrail_stop`) / 에스컬레이션(`escalated_by` 별) / 기타
- 시나리오별 (관측) : "k / n 미완료"(DM-6), 첫 STOP step·템플릿 분포·원인 설명 문장 예, 정상판의 STOP(성공·에스컬레이션 세션의 STOP 을 오탐으로 따로),
  교착판의 미완료 중 STOP(탐지), 아낄 토큰 비율 평균과 아낄 크레딧 합, 실측·추정 크레딧, 실패 step 사유별, 첫 STOP 판정 창 안의 어휘 위반 step 수
- **탐지 지연** : 첫 STOP step − 교착 시작. 교착 시작은 S-27 대로 판정기와 독립인 결과 신호(인수 테스트 통과 수, 작업 공간 상태 해시)가 마지막으로 바뀐 다음 step.
  산출물 과제(T2·T3)만 계산하고, T1 은 그런 신호가 없어 계산하지 않는다 (출력에 방법과 함께 적음). 음수는 조기 STOP 으로 따로 세고 중앙값에서 뺀다 (S-20).
  시험 세션 값 : CL 교착판 +6 (교착 시작 9, STOP 15). CT 교착판 −21 : 늦은 승인·편집(step 27~29)으로 결과가 바뀌어 "끝까지 회복 없는 구간" 이 step 30 에서 시작하므로
  step 9 의 STOP 은 정의상 조기 STOP 이다
- 차단 세션 : 같은 시나리오 관측 세션 평균 대비 토큰·추정 크레딧 차이로만 보고 (DM-23)
- 유형별(T1·T2·T3) 표, 전체 요약(발표용 숫자 : 정상판 STOP·오탐, 교착판 미완료·탐지·에스컬레이션, 탐지된 교착판의 평균 아낄 토큰 비율, 실측 크레딧 합),
  계정별 실측 크레딧. 모든 숫자에 "데모 세션 기준" (DM-2)
- **대표 세션 규칙** : 교착판(과 CT-N)마다 첫 STOP 이 있는 관측 세션 중 가장 많은 첫 STOP 템플릿(같으면 ID 순)을 고르고, 그중 첫 STOP step 이 아래 중앙값인 세션
  (같으면 세션 ID 순). 정상판마다 성공 관측 세션 중 step 수가 아래 중앙값인 세션. 근거 문장을 출력에 남긴다
- 출력 : JSON + Markdown. 시험 세션 집계 예 `reports/c19-1/aggregate-trials.{json,md}`

## 재생 페이지 (`render`, `index`, `pages`)

- 세션 하나에 HTML 파일 하나 : 스타일·스크립트·데이터(재생 기록 JSON)를 파일 안에 넣고 외부 자원을 쓰지 않는다. JSON 안의 `</` 는 이스케이프한다
- step 을 넘겨 보기(이전/다음, 슬라이더, 방향키, "첫 STOP 으로"), 사실 요약, 판정 상태(진전/정체/되돌림), STOP 표시와 원인 설명 문장,
  누적 토큰 그래프와 첫 STOP·403 차단 표시선, 관측 세션은 "여기서 멈췄다면" 아낄 양, step 표
- `pages` 는 집계의 대표 세션마다 페이지와 `index.html`(유형별 목록, 선정 근거) 을 만든다
- 예시 : `reports/c19-1/replay-examples/` (CL 교착판, CT 교착판, CS 시험 두 세션, MR 정상판 시험, 정상판 대표 3 개, index)
