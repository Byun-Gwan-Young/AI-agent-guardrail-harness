# DEMO-CL parse_duration 수정 계획

## 현황 (초기 인수 테스트 결과)
- 15개 중 6개 통과, 8개 실패, 1개 에러.
- 현재 src/duration.py는 "숫자+단위" 쌍을 단순 findall로 더하기만 하므로
  잘못된 입력 검증이 전혀 없고, 시간 뒤 분 생략 표기("1h30")와 대소문자도 미지원.

## 지켜지지 않는 인수 조건과 고칠 순서
1. (조건 6) 문자열이 아닌 입력은 TypeError - `isinstance(text, str)` 검사를
   가장 먼저 둔다. ("90".isdigit()가 비문자열에서 에러를 내는 문제도 함께 해소)
2. (조건 2) 입력 정규화 - `text.strip()`으로 앞뒤 공백 제거, 단위 비교는 소문자로.
3. (조건 1, 3, 4) 형식 파싱 - 전체 문자열이 아래 패턴과 정확히 일치해야 한다:
   `^(\d+)h?(\d+)?m?(\d+)?s?$` 형태의 단일 fullmatch 정규식으로,
   - h 생략형: `1h30` → 30을 분으로 처리 (조건 4)
   - 각 단위는 최대 한 번, h → m → s 순서 (조건 1)
   - 단위가 전혀 없으면 초 (조건 3)
   fullmatch 실패 또는 단위 순서/반복 위반이면 ValueError.
4. (조건 5) ValueError 케이스 - 빈 문자열, 숫자 없는 단위("h"),
   정해지지 않은 글자("1h30x"), 순서 틀림("30m1h"), 반복("1m1m"),
   부호("-5s")는 모두 fullmatch가 거부하므로 같은 경로에서 ValueError.
5. 계산: h*3600 + m*60 + s를 반환. ("1h30m"=5400, "1h30"=5400, " 3m "=180, "0s"=0)

## 구현 스케치 (src/duration.py 교체)
- TypeError: str이 아니면 raise TypeError.
- s = text.strip().lower(); s가 빈 문자열이면 ValueError.
- 정규식: `^(\d+)(h(\d+)?)?(m(\d+)?)?(s(\d+)?)?$` 를 fullmatch.
- 매칭 결과에서 단위 등장 여부/순서를 확인해 h, m, s 순서 위반이나
  반복은 ValueError (정규식이 이미 대부분 걸러 주지만 명시적으로도 확인).
- 값: 시간 그룹의 뒷숫자(있으면)는 분으로 합산.
